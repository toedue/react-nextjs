# React Components

Components are the building blocks of a React application. They are independent, reusable pieces of code that serve the same purpose as JavaScript functions, but work in isolation and return HTML via JSX.

---

## Two Types of Components

In React, there are two main ways to create a component: **Function Components** and **Class Components**.

### 1. Function Components

This is the modern and most common way to write components. A Function component is just a plain JavaScript function that returns JSX.

```javascript
function Welcome() {
  return <h1>Hello, I am a Function Component!</h1>;
}
```

### 2. Class Components

Before React 16.8 (Hooks), Class components were the only way to track state and lifecycle. They are still supported but are no longer the recommended way to write new code.

```javascript
class Welcome extends React.Component {
  render() {
    return <h1>Hello, I am a Class Component!</h1>;
  }
}
```

---

## Component Rules

1. **Capitalized Names:** Component names must always start with an uppercase letter (e.g., `Welcome`, not `welcome`). React treats components starting with lowercase letters as DOM tags (like `<div>` or `<h1>`).
2. **Return JSX:** A component must return a single React element (or a group of elements wrapped in a single parent or Fragment).

---

## Using a Component

Once a component is defined, it can be used inside other components just like an HTML tag.

```javascript
function App() {
  return (
    <div>
      <Welcome />
      <Welcome />
    </div>
  );
}
```

---

## Components in Files

To keep code organized, components are typically created in separate files and exported.

**File: Welcome.js**

```javascript
function Welcome() {
  return <h1>Hello from a separate file!</h1>;
}

export default Welcome;
```

**File: App.js**

```javascript
import Welcome from "./Welcome.js";

function App() {
  return <Welcome />;
}
```

---

## Props (Properties)

Components can accept arguments, called **props**. Props are passed to the component via HTML attributes and allow you to make components dynamic and reusable.

```javascript
function Greeting(props) {
  return <h1>Hello, {props.name}!</h1>;
}

function App() {
  return <Greeting name="Alice" />;
}
```

# React Component Conventions

Following standard conventions ensures that your React code is readable, maintainable, and compatible with the way React distinguishes between HTML elements and custom components.

---

## 1. Naming Conventions

### PascalCase for Components

All React component names must start with an uppercase letter. This is known as **PascalCase**.

- **Correct:** `UserCard`, `Header`, `MainButton`
- **Incorrect:** `userCard`, `header`, `main_button`

React uses this convention to distinguish between HTML tags and components. If a tag starts with a lowercase letter, React treats it as a built-in HTML element (like `<div>` or `<span>`).

### CamelCase for Props and Methods

While the component itself uses PascalCase, the properties (props) passed to it and the functions inside it should use **camelCase**.

- **Example:** `<UserCard userName="John" isActive={true} />`

---

## 2. File Organization

### One Component Per File

For better maintainability, it is a standard practice to define only one component per file. The filename should match the component name exactly.

- **Component:** `UserProfile`
- **Filename:** `UserProfile.js` or `UserProfile.jsx`

### Folder Structure

Large components are often placed in their own folder along with their specific styles or tests.

- `src/components/UserCard/UserCard.js`
- `src/components/UserCard/UserCard.css`

---

## 3. Component Structure

A standard function component follows a specific order of code:

1. **Imports:** React, hooks, styles, and sub-components.
2. **Component Function:** The logic and state definitions.
3. **Return Statement:** The JSX that defines the UI.
4. **Export:** Making the component available for other files.

```javascript
// 1. Imports
import React, { useState } from "react";

// 2. Component Function (PascalCase)
function SearchBar() {
  const [query, setQuery] = useState("");

  // 3. Return Statement
  return (
    <input
      type="text"
      value={query}
      onChange={(e) => setQuery(e.target.value)}
    />
  );
}

// 4. Export
export default SearchBar;
```

---

## 4. JSX Conventions

### Multi-line JSX

If your JSX spans more than one line, always wrap it in parentheses `()` to avoid JavaScript's automatic semicolon insertion issues.

```javascript
return (
  <div>
    <h1>Title</h1>
    <p>Content</p>
  </div>
);
```

### Self-Closing Tags

If a component does not have any children (no content between opening and closing tags), use a self-closing tag.

- **Correct:** `<Header />`
- **Avoid:** `<Header></Header>`

# Steps to Writing Functional Components

A functional component is a JavaScript function that returns JSX. Since React 16.8, these are the standard way to build components using Hooks.

---

## 1. Import React (Optional in Modern React)

In older versions, you had to import React at the top. In modern React (version 17+), this is often handled automatically by the build tool, but you still need to import **Hooks** if you plan to use them.

```javascript
import React, { useState } from "react";
```

---

## 2. Define the Function

Create a function using the `function` keyword or an arrow function. Ensure the name follows the **PascalCase** convention (starts with a capital letter).

```javascript
// Using function keyword
function MyComponent() {
  // logic goes here
}

// OR using Arrow Function
const MyComponent = () => {
  // logic goes here
};
```

---

## 3. Handle Props (Optional)

If the component needs data from its parent, pass `props` as an argument to the function. You can also use **destructuring** to extract specific values directly.

```javascript
function Welcome(props) {
  return <h1>Hello, {props.name}</h1>;
}

// Using destructuring (Cleaner)
function Welcome({ name }) {
  return <h1>Hello, {name}</h1>;
}
```

---

## 4. Define Logic and State

Inside the function body (before the `return` statement), you can define variables, functions, and use Hooks like `useState` or `useEffect`.

```javascript
function Counter() {
  const [count, setCount] = useState(0);

  const increment = () => {
    setCount(count + 1);
  };

  // Logic is defined here...
}
```

---

## 5. Return JSX

Every component must return the UI description in the form of JSX. Use parentheses `()` if the JSX spans multiple lines. Remember that you must return only **one single root element**.

```javascript
return (
  <div>
    <p>Count: {count}</p>
    <button onClick={increment}>Increment</button>
  </div>
);
```

---

## 6. Export the Component

To use this component in other parts of your app, you must export it.

```javascript
export default MyComponent;
```

---

## Complete Example

```javascript
import React, { useState } from "react";

function UserProfile({ username }) {
  const [status, setStatus] = useState("Online");

  return (
    <div className="profile-card">
      <h2>User: {username}</h2>
      <p>Status: {status}</p>
      <button onClick={() => setStatus("Offline")}>Go Offline</button>
    </div>
  );
}

export default UserProfile;
```
