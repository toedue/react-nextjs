# React Elements

In React, an **element** is the smallest building block of an application. It describes what you want to see on the screen.

---

## What is a React Element?

A React element is a plain JavaScript object that represents a DOM node or a component. Unlike browser DOM elements, React elements are cheap to create and are immutable.

### Element vs. Component

* **Element:** A description of a single node (e.g., a `div` or a `button`).
* **Component:** A function or class that can accept inputs (props) and returns a React element tree.

---

## Creating React Elements

### Using JSX

The most common way to create an element is using JSX. It looks like HTML but is converted by tools like Babel into JavaScript.

```javascript
const element = <h1>Hello, World!</h1>;

```

### Using JavaScript (Without JSX)

Behind the scenes, JSX is converted into the `React.createElement()` function.

```javascript
const element = React.createElement(
  'h1',
  { className: 'greeting' },
  'Hello, World!'
);

```

The `createElement()` method takes three arguments:

1. **Type:** The HTML tag name (like 'h1' or 'div') or a React component.
2. **Props:** An object containing attributes (like `className` or `id`).
3. **Children:** What goes inside the element (text, other elements, or components).

---

## Rendering an Element into the DOM

To render a React element into the browser, you first need a "root" DOM node in your HTML file:

```html
<div id="root"></div>

```

Then, use `ReactDOM.createRoot()` to manage that area and the `.render()` method to display the element:

```javascript
const root = ReactDOM.createRoot(document.getElementById('root'));
const element = <h1>Hello, React!</h1>;
root.render(element);

```

---

## Elements are Immutable

Once you create a React element, you cannot change its attributes or children. An element is like a single frame in a movie: it represents the UI at a specific point in time.

### How to update the UI

To change what appears on the screen, you must:

1. Create a new element.
2. Pass it to `root.render()` again.

React's Virtual DOM efficiently compares the new element with the previous one and only applies the necessary updates to the Real DOM.

---

## Summary

* **Elements** are the smallest units in React.
* They are **objects**, not actual DOM nodes.
* They are **immutable**.
* JSX is the standard way to write them, but they translate to `React.createElement()`.

---

# React.createElement

In React, `React.createElement()` is the method used to create a React element. While most developers use JSX, `React.createElement()` is what JSX actually compiles into.

---

## Syntax

The function accepts three main arguments:

```javascript
React.createElement(type, [props], [...children])

```

1. **type**: A string representing an HTML tag (like 'div' or 'span'), or a React component (a function or a class).
2. **props**: (Optional) An object containing properties/attributes passed to the element (like `className`, `id`, or custom props). Use `null` if no props are needed.
3. **children**: (Optional) Anything contained inside the element. This can be text, other React elements, or an array of elements.

---

## Comparison: JSX vs. createElement

JSX is simply "syntactic sugar" for `React.createElement()`.

### Using JSX

```javascript
const myElement = <h1 className="title">Hello World</h1>;

```

### Using createElement

```javascript
const myElement = React.createElement(
  'h1',
  { className: 'title' },
  'Hello World'
);

```

Both code snippets result in the same JavaScript object that describes the UI.

---

## Nesting Elements

You can nest `createElement` calls to build complex structures. This demonstrates how React builds a tree of elements.

### JSX Example

```javascript
const myContainer = (
  <div id="container">
    <h1>Title</h1>
    <p>Description</p>
  </div>
);

```

### Pure JavaScript Example

```javascript
const myContainer = React.createElement(
  'div',
  { id: 'container' },
  React.createElement('h1', null, 'Title'),
  React.createElement('p', null, 'Description')
);

```

---

## Why Use createElement?

Most of the time, you will use JSX because it is easier to read and write. However, understanding `createElement` is important because:

* **No Build Tools:** You can use React without a compiler (like Babel) by writing pure `createElement` calls.
* **Dynamic Elements:** It is useful when you need to create elements dynamically based on logic that might be awkward in JSX.
* **Under the Hood:** It helps you understand that React is just JavaScript and that elements are just objects.

---

## Summary

* **React.createElement** is the core method for creating elements.
* **JSX** is converted into these calls during the build process.
* **Elements are objects** that describe what should appear on the screen.

# ReactDOM.render

In React, `ReactDOM.render()` was the standard method used to render a React element into the browser's DOM. However, since **React 18**, this has been replaced by the `createRoot` API for better performance and to enable new features.

---

## The Old Way (Before React 18)

In older versions of React, you used `ReactDOM.render()` directly. It takes two arguments: the element you want to render and the DOM container where it should go.

```javascript
import React from 'react';
import ReactDOM from 'react-dom';

const myElement = <h1>Hello React!</h1>;

ReactDOM.render(myElement, document.getElementById('root'));

```

---

## The New Way (React 18+)

React 18 introduced `ReactDOM.createRoot()`. This change was made to support **Concurrent Rendering**, which makes apps feel more responsive.

### Steps to render:

1. **Find the root element:** Select the HTML element (usually a `div` with `id="root"`) from your `index.html`.
2. **Create a root:** Use `ReactDOM.createRoot()` to create a React root.
3. **Render the element:** Call the `.render()` method on that root.

```javascript
import React from 'react';
import ReactDOM from 'react-dom/client';

const myElement = <h1>Hello React 18!</h1>;

// 1. Create the root
const root = ReactDOM.createRoot(document.getElementById('root'));

// 2. Render the element
root.render(myElement);

```

---

## Important Differences

| Feature | ReactDOM.render (Old) | createRoot (New) |
| --- | --- | --- |
| **Import Path** | `react-dom` | `react-dom/client` |
| **Performance** | Basic rendering | Supports Concurrent features |
| **Syntax** | `render(element, container)` | `createRoot(container).render(element)` |

---

## How it Works Under the Hood

When you call `.render()`, React does the following:

1. **Clears Content:** It replaces any existing content inside the "root" DOM node with the React element.
2. **Mounting:** It converts the React elements into real DOM nodes and inserts them into the page.
3. **Updates:** If you call `.render()` again on the same root with a different element, React performs its "diffing" algorithm to update only the parts of the DOM that changed.

---

## Summary

* **ReactDOM** is the package that provides DOM-specific methods.
* **createRoot** is the modern entry point for React applications.
* You typically only call this once in your entire application, usually in the `index.js` or `main.js` file.

---

# React 18 createRoot and StrictMode

In React 18, the standard way to initialize an application is by using `createRoot` and wrapping the main component in `StrictMode`. This code is typically found in the `index.js` or `main.jsx` file.

---

## Breakdown of the Code

### 1. createRoot()

`createRoot` is part of the `react-dom/client` package. It creates a React root at the specified HTML element, allowing React to manage the DOM within that container.

* **document.getElementById('root')**: This targets a specific `div` in your `index.html` file where the entire application will be injected.

### 2. .render()

The `.render()` method is called on the root object. It takes the React elements (JSX) and displays them inside the target DOM node.

---

## 3. StrictMode

`<StrictMode>` is a tool for highlighting potential problems in an application. It does not render any visible UI.

### What StrictMode does:

* **Identifies unsafe lifecycles:** Warns if you use deprecated class component methods.
* **Warning about legacy API usage:** Notifies you if you are using older React features that may be removed in the future.
* **Detecting unexpected side effects:** In Development mode, React will intentionally **double-invoke** certain functions (like the component body, `useState` updaters, and `useEffect`) to help find bugs.
* **Ensuring reusable state:** Helps identify if your components are resilient to being unmounted and remounted.

---

## 4. ```<App />```

This is your root component. It contains the entire logic and structure of your application. Everything inside `<App />` will be subject to the checks performed by `<StrictMode>`.

---

## Comparison: Development vs. Production

| Feature | Development Mode | Production Mode |
| --- | --- | --- |
| **Double Rendering** | Yes (to find bugs) | No (normal performance) |
| **Console Warnings** | Detailed and frequent | Minimal |
| **Performance Checks** | Active | Disabled |

---

## Summary

* **createRoot** is the entry point for React 18 applications.
* **StrictMode** is a development-only tool that helps write better code by catching bugs early.
* **App** is the starting point of your component tree.
