# React State, setState(), and Class Component Lifecycle – Complete Notes

These are fundamental concepts in **React Class Components**. Although modern React uses **Hooks** (`useState`, `useEffect`), understanding these concepts is important because many existing React projects still use class components.

---

# 1. React State

## Definition

**State is an object that stores data belonging to a component.**

Unlike props, **state can change** while the application is running.

---

## Real-Life Example

Imagine a counter app.

Initially,

```
Count = 0
```

When you click the button,

```
Count = 1

↓

Count = 2

↓

Count = 3
```

The changing value is stored inside **state**.

---

# Why Do We Need State?

Without state:

```jsx
function App() {
    return <h1>0</h1>;
}
```

The value never changes.

With state:

```
0

↓

1

↓

2

↓

3
```

React automatically updates the UI whenever the state changes.

---

# State vs Props

| Props              | State                  |
| ------------------ | ---------------------- |
| Passed from parent | Owned by the component |
| Read-only          | Can change             |
| External data      | Internal data          |
| Parent updates it  | Component updates it   |

---

# State in Class Components

State is created inside the constructor.

```jsx
import React, { Component } from "react";

class Counter extends Component {

    constructor() {
        super();

        this.state = {
            count: 0
        };
    }

    render() {
        return (
            <h1>{this.state.count}</h1>
        );
    }

}

export default Counter;
```

Output

```
0
```

---

# Accessing State

Always use

```javascript
this.state
```

Example

```jsx
<p>{this.state.count}</p>
```

or

```jsx
<h2>{this.state.name}</h2>
```

---

# State with Multiple Values

```jsx
this.state = {

    name: "John",

    age: 22,

    city: "London"

};
```

Access

```jsx
<h1>{this.state.name}</h1>

<p>{this.state.age}</p>

<p>{this.state.city}</p>
```

# 2. setState()

## Definition

`setState()` is the method used to update the component's state.

Never modify state directly.

---

## Wrong Way ❌

```javascript
this.state.count = 10;
```

React will not re-render correctly.

---

## Correct Way ✅

```javascript
this.setState({

    count: 10

});
```

React updates the UI automatically.

---

# Counter Example

```jsx
import React, { Component } from "react";

class Counter extends Component {

    constructor() {

        super();

        this.state = {

            count: 0

        };

    }

    increase = () => {

        this.setState({

            count: this.state.count + 1

        });

    };

    render() {

        return (

            <div>

                <h1>{this.state.count}</h1>

                <button onClick={this.increase}>
                    Increment
                </button>

            </div>

        );

    }

}

export default Counter;
```

Output

```
0

[Increment]

↓

1

↓

2

↓

3
```

---

# Updating Multiple Values

```jsx
this.setState({

    name: "Ali",

    age: 20

});
```

---

# Functional setState()

If the new state depends on the previous state, use the functional form.

```jsx
this.setState((prevState) => ({

    count: prevState.count + 1

}));
```

This avoids issues with asynchronous updates.

---

# Why is setState() Used?

```
Old State

↓

setState()

↓

React Updates State

↓

React Re-renders UI
```

---

# React Re-rendering

Whenever `setState()` is called,

React:

```
Changes State

↓

Calls render()

↓

Updates Browser
```

You don't manually update the HTML. React does it for you.

# 3. React Component Lifecycle (Class Components)

Every React class component goes through three main phases:

```
Creation

↓

Update

↓

Removal
```

---

## Lifecycle Diagram

```text

↓

Render

↓

componentDidMount()

↓

User Interaction

↓

setState()

↓

shouldComponentUpdate()

↓

Render

↓

componentDidUpdate()

↓

componentWillUnmount()
```

---

# Phase 1: Mounting

Mounting means the component is being created and added to the page.

Methods:

```
constructor()

↓

render()

↓

componentDidMount()
```

---

## constructor()

Runs first.

Used for:

* Initializing state
* Binding methods

Example

```jsx
constructor() {

    super();

    this.state = {

        count: 0

    };

}
```

---

## render()

Returns JSX.

```jsx
render() {

    return (

        <h1>Hello</h1>

    );

}
```

This method is required in every class component.

---

## componentDidMount()

Runs after the component appears on the screen.

Used for:

* API calls
* Timers
* Event listeners

Example

```jsx
componentDidMount() {

    console.log("Component Mounted");

}
```

Output

```
Component Mounted
```

---

# Phase 2: Updating

Occurs whenever:

* Props change
* State changes (`setState()`)

Methods:

```
shouldComponentUpdate()

↓

render()

↓

componentDidUpdate()
```

---

## shouldComponentUpdate()

Decides whether the component should re-render.

Example

```jsx
shouldComponentUpdate() {

    return true;

}
```

Returning

```javascript
false
```

prevents re-rendering.

---

## componentDidUpdate()

Runs after every update.

Example

```jsx
componentDidUpdate() {

    console.log("Updated");

}
```

Output

```
Updated
```

---

# Phase 3: Unmounting

When the component is removed from the screen.

Method

```
componentWillUnmount()
```

---

## componentWillUnmount()

Used to clean up resources.

Examples:

* Remove timers
* Remove event listeners
* Cancel API requests

Example

```jsx
componentWillUnmount() {

    console.log("Component Removed");

}
```

---

# Complete Lifecycle Example

```jsx
import React, { Component } from "react";

class Demo extends Component {

    constructor() {

        super();

        console.log("Constructor");

        this.state = {

            count: 0

        };

    }

    componentDidMount() {

        console.log("Mounted");

    }

    componentDidUpdate() {

        console.log("Updated");

    }

    componentWillUnmount() {

        console.log("Unmounted");

    }

    increase = () => {

        this.setState({

            count: this.state.count + 1

        });

    };

    render() {

        console.log("Render");

        return (

            <div>

                <h1>{this.state.count}</h1>

                <button onClick={this.increase}>
                    Increment
                </button>

            </div>

        );

    }

}

export default Demo;
```

# Class Components vs Functional Components

| Class Component          | Functional Component                       |
| ------------------------ | ------------------------------------------ |
| `this.state`             | `useState()`                               |
| `this.setState()`        | State setter function (`setCount`)         |
| `componentDidMount()`    | `useEffect(() => {}, [])`                  |
| `componentDidUpdate()`   | `useEffect(() => {}, [dependencies])`      |
| `componentWillUnmount()` | Cleanup function returned from `useEffect` |

---

# Modern Equivalent

### Class Component

```jsx
class Counter extends React.Component {

    state = {

        count: 0

    };

}
```

### Functional Component

```jsx
const [count, setCount] = useState(0);
```

---

### Class Component

```jsx
componentDidMount() {

    console.log("Mounted");

}
```

### Functional Component

```jsx
useEffect(() => {

    console.log("Mounted");

}, []);
```

# Summary Table

| Concept                   | Purpose                                      | Example                               |
| ------------------------- | -------------------------------------------- | ------------------------------------- |
| State                     | Stores component data                        | `this.state = { count: 0 }`           |
| `this.state`              | Reads state values                           | `this.state.count`                    |
| `setState()`              | Updates state and triggers a re-render       | `this.setState({ count: 1 })`         |
| `constructor()`           | Initializes state and sets up the component  | `constructor() { super(); }`          |
| `render()`                | Returns the JSX to display                   | `render() { return <h1>Hello</h1>; }` |
| `componentDidMount()`     | Runs after the component is added to the DOM | Fetch data, start timers              |
| `shouldComponentUpdate()` | Controls whether a re-render should happen   | `return true;`                        |
| `componentDidUpdate()`    | Runs after state or props change             | Respond to updates                    |
| `componentWillUnmount()`  | Cleans up before the component is removed    | Clear timers, remove listeners        |

## Important Interview Points

* **State** stores data that can change over time.
* **Never modify `this.state` directly**; always use **`this.setState()`**.
* Calling **`setState()`** schedules a state update and causes React to re-render the component.
* The three lifecycle phases are:

  1. **Mounting**
  2. **Updating**
  3. **Unmounting**
* In modern React, **functional components with Hooks (`useState`, `useEffect`)** are the preferred approach, but understanding class components is valuable for maintaining older React applications.
