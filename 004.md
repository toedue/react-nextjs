# What is Synchronous Programming?

**Definition:**

Synchronous code executes **one line at a time**, in order. The next line cannot run until the current one finishes.

Imagine you're standing in a queue at a bank.

```
Person A
   ↓
Person B
   ↓
Person C
```

Each person waits for the previous one to finish.

### Example

```javascript
console.log("Start");

console.log("Middle");

console.log("End");
```

Output

```
Start
Middle
End
```

Execution

```
Line 1
 ↓
Line 2
 ↓
Line 3
```

Everything happens one after another.

---

# The Problem

Imagine this code:

```javascript
console.log("Start");

// takes 5 seconds
downloadFile();

console.log("End");
```

If `downloadFile()` takes **5 seconds**, JavaScript waits.

```
Start

(wait 5 seconds)

End
```

During those 5 seconds, **nothing else happens**.

The whole program is blocked.

This is called **blocking**.

---

# Real-Life Example

Suppose you're cooking.

### Synchronous

```
Boil water (10 minutes)

↓

Cook pasta (10 minutes)

↓

Make sauce (10 minutes)
```

Total

```
30 minutes
```

You wait every time.

---

# Asynchronous Programming

Now imagine you're smarter.

```
Start boiling water

↓

While it boils,
make the sauce

↓

When water is ready,
cook pasta
```

Total

```
About 20 minutes
```

You don't waste time waiting.

This is asynchronous programming.

---

# Definition

Asynchronous programming lets JavaScript **start a task and continue doing other work while waiting for that task to finish**.

Instead of blocking the program, JavaScript says:

> "I'll come back when this task is done."

---

# Example

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Hello");
}, 3000);

console.log("End");
```

### Output

```
Start
End
Hello
```

Notice something strange?

Even though `setTimeout()` is in the middle, `"End"` prints first.

Why?

Because JavaScript doesn't wait.

It says:

```
Start timer.

↓

Continue.

↓

After 3 seconds,
run this function.
```

Timeline

```
Start
↓

setTimeout()

↓

End

↓

3 seconds

↓

Hello
```

# Why JavaScript Uses Asynchronous Programming

JavaScript originally ran inside browsers.

Imagine visiting YouTube.

If JavaScript were completely synchronous:

```
Download comments

↓

Wait

↓

Download recommendations

↓

Wait

↓

Download video information

↓

Wait
```

The page would freeze.

Instead:

```
Download comments

Download recommendations

Download video information

↓

Keep the page responsive
```

Everything feels smooth.

# JavaScript Is Single-Threaded

This confuses many beginners.

JavaScript has **one call stack**.

It can execute **only one piece of JavaScript code at a time**.

```
Call Stack

↓

Function A

↓

Function B

↓

Function C
```

So how does it do asynchronous work?

The answer is:

**The browser (or Node.js) helps JavaScript.**

---

# The Browser Helps

When JavaScript sees

```javascript
setTimeout(...)
```

it doesn't wait.

Instead:

```
JavaScript

↓

Ask browser:

"Please keep track of this timer."

↓

Continue running code.
```

The browser watches the timer.

When it's finished, it tells JavaScript.

---

# Event Loop

This is the heart of asynchronous JavaScript.

There are three important parts.

```
Call Stack

Web APIs

Callback Queue
```

Let's understand each.

---

## 1. Call Stack

Runs JavaScript code.

```
console.log()

↓

function()

↓

another function()
```

Only one thing runs here at a time.

---

## 2. Web APIs

The browser handles asynchronous tasks.

Examples:

* `setTimeout`
* `fetch`
* DOM events
* Mouse clicks
* Keyboard events

---

## 3. Callback Queue

When an async task finishes:

```
Finished

↓

Put callback here
```

Example

```
console.log("Hello")
```

waits until the stack becomes empty.

---

# Event Loop

The Event Loop constantly checks:

```
Is the Call Stack empty?

↓

Yes?

↓

Move callback from queue

↓

Execute it
```

This checking happens continuously.

---

# Common Asynchronous Operations

## Timers

```javascript
setTimeout(() => {
    console.log("Hi");
}, 1000);
```

---

## Intervals

```javascript
setInterval(() => {
    console.log("Tick");
}, 1000);
```

Runs every second.

---

## Fetch API

```javascript
fetch("https://jsonplaceholder.typicode.com/users")
```

Downloading data is asynchronous.

---

## Button Clicks

```javascript
button.addEventListener("click", () => {
    console.log("Clicked");
});
```

JavaScript waits until the user clicks.

# Ways to Handle Asynchronous Code

Over the years, JavaScript introduced three main approaches.

## 1. Callbacks

```javascript
setTimeout(() => {
    console.log("Done");
}, 1000);
```

Oldest approach.

---

## 2. Promises

```javascript
fetch(url)
.then(response => response.json())
.then(data => console.log(data));
```

Cleaner than callbacks.

---

## 3. Async/Await

```javascript
async function getUsers() {
    const response = await fetch(url);

    const data = await response.json();

    console.log(data);
}
```

This is the modern and most readable approach.

# Summary

| Synchronous                  | Asynchronous                               |
| ---------------------------- | ------------------------------------------ |
| One task at a time           | Can start a task and continue with others  |
| Blocking                     | Non-blocking                               |
| Waits for each operation     | Doesn't wait for long-running operations   |
| Simpler execution order      | Uses callbacks, promises, or `async/await` |
| Example: normal calculations | Example: API requests, timers, user events |
